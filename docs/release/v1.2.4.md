## lan disk 1.2.4

**大文件不再需要下载完才能预览**，视频改为流式播放；WMV 这类浏览器解不了的格式给出明确提示。

### 之前为什么慢

1. 预览用的 `/raw` 返回 `application/octet-stream` + `attachment`，浏览器拿到这种响应不会就地播放，只能把整个文件收完；
2. FileViewer 的媒体渲染接口是 `render(buffer, …)`——**文件先整包读进内存**再交给播放器，2 GB 视频等于先下载 2 GB。

### 现在

- 新增 **`GET /api/shares/{id}/content`**：按扩展名给出正确 MIME（`video/mp4`、`video/x-matroska`…）、`Content-Disposition: inline`、`X-Content-Type-Options: nosniff`，并由 `http.ServeContent` 处理 Range——`206` + `Content-Range` + `Accept-Ranges`。`/raw` 保留为下载（attachment）。
- **视频/音频用浏览器原生 `<video>`/`<audio>` 播放**（mp4/m4v/webm/ogv/mov/mkv、mp3/wav/m4a/aac/flac/ogg/opus），直接吃 `/content`：打开即播、拖进度条即时定位、支持画中画与原生控件。
- **WMV / WMA / AVI / RMVB / FLV / MPEG 等**：Chromium 内核本来就不支持这些解码，页面改为显示「浏览器无法播放该格式」并给出下载按钮，不再抛 `DEMUXER_ERROR_COULD_NOT_OPEN`；能播的容器里遇到不支持的编码（H.265 / ProRes 等）时，`<video @error>` 会提示改用本地播放器。

### 实测

- 8 MB 的 `.mp4`：浏览器请求 `/content` 时带 `Range: bytes=0-`（换成流式前的请求不带 Range），服务端返回 `206`、`Content-Range: bytes 0-999/8000000`、`Content-Type: video/mp4`。
- `.wmv` 预览页显示：`浏览器无法播放该格式 · 请下载后用本地播放器打开` + 下载按钮。

### 升级

覆盖 `lanDisk.exe` → `lanDisk.exe uninstall` / `install` → Ctrl+F5；`landisk.db` 不动。
