## lan disk 1.2.3

**兜底：预览运行时资源同时挂在 `/file-viewer/` 与站根两个前缀下**，并给 `/api/health` 增加资源自检。

### 为什么

现场又出现：

```
Setting up fake worker failed: "Failed to fetch dynamically imported module:
http://10.7.39.16/vendor/pdf/pdf.worker.mjs"
```

路径里**没有 `/file-viewer/`**，这正是 1.0.3 修复前的解析方式（预览器按文档基准地址拼资源）。1.0.3 起我们把每条链路的 worker/wasm 都写成 `/file-viewer/...` 绝对路径，所以**跑着这个报错的机器大概率是旧版本**（`lanDisk.exe version` 或页脚版本号可确认）。

### 这次做的两件事

1. **别名兜底**：服务端把 `/vendor/*`、`/wasm/*` 映射到内嵌的 `/file-viewer/vendor/*`、`/file-viewer/wasm/*`。即使某个版本的预览器或某次改动把路径拼回了站根，也会拿到正确文件，而不是 404/HTML。
2. **部署自检**：`GET /api/health` 增加 `preview_assets`（内嵌的预览资源文件数，完整构建约 337）。现场只要 `curl http://<host>/api/health` 就能判断：
   - `preview_assets: 0` → 这个 exe 没带预览资源（构建方式不对）；
   - `version` < `1.1.2` → 老版本，升级到最新；
   - `preview_assets` 正常但预览仍报错 → 用浏览器网络面板看实际请求的 URL。

### 现场处理

覆盖为新版 `lanDisk.exe` → `uninstall` / `install` → Ctrl+F5。实测（1.2.3）：`/vendor/pdf/pdf.worker.mjs` 与 `/file-viewer/vendor/pdf/pdf.worker.mjs` 都返回 `200 text/javascript`；不存在的文件仍是 404；`/api/health` 返回 `preview_assets: 337`。
