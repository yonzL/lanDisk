## lan disk 1.0.3

**修复现场部署后 PDF 预览报错**：`Setting up fake worker failed: "Failed to fetch dynamically imported module: http://<host>/vendor/pdf/pdf.worker.mjs"`。

### 原因

预览器默认按“文档基准地址”拼装运行时资源，PDF worker 被解析成了站根路径 `/vendor/pdf/pdf.worker.mjs`（缺 `/file-viewer` 前缀）。这类路径又被 SPA 回落接住、返回 `index.html`，于是浏览器把 HTML 当模块导入，报出 `Unexpected token '<'` / `Failed to fetch dynamically imported module`。

本地测试没暴露，是因为同一份代码在测试环境里走了全局资源基地址；换一台机器/一个端口后基准地址不同，问题就出现了。

### 修复

- **每个渲染链路的运行时资源都显式指定绝对路径**（都以 `/file-viewer/` 开头）：PDF（worker / cmaps / wasm / standard_fonts）、Word、PPT、Excel、压缩包、CAD、3D 模型。不再依赖“全局基地址 + 文档地址”的隐式拼装。
- **丢前缀的资源路径现在直接 404**（不再返回 SPA 的 HTML）：`/vendor/*`、`/wasm/*` 与 `/file-viewer/*` 一样按静态资源处理，缺失即 404，日志与网络面板能一眼看出是路径问题而不是模块语法错误。

### 验证（1.0.3 构建）

用无头 Edge 抓了 PDF 预览的全部网络请求：运行时资源**只**请求了 `/file-viewer/vendor/pdf/pdf.worker.mjs`，没有任何站根相对路径，控制台无错误；PDF 正常渲染（“Hello lanDisk” + 页码/缩放/搜索工具栏）。另外确认 `/vendor/pdf/pdf.worker.mjs` 返回 404 而不是 HTML。

### 升级

覆盖 `lanDisk.exe` → `lanDisk.exe uninstall` / `install`（或重启服务）→ 浏览器 **Ctrl+F5** 强刷一次预览页。数据文件 `landisk.db` 不变。
